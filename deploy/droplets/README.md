## Closed campaign and dev reset controls (September 30)

Set `SITE_STATE=closed` in production's protected environment and restart the app. Public pages redirect to `/closed`; collection APIs return 503. Keep `ENABLE_SUBMISSIONS=false` as a second gate. Health checks and authenticated admin routes stay available. Dev uses `SITE_STATE=open`. Opening production requires a separate approved launch, not a readiness test.

Dev-only admin backup/reset requires `ENABLE_TEST_DATA_TOOLS=true`, `PROXY_TEST_MODE=true`, and the exact dev APP_URL. Production cannot use it. The operator can create a backup without deleting anything. To clear, type `CLEAR DEV TESTS` and press the explicit backup-and-clear button. The backup is written and read back with a SHA-256 check before row deletion. The tool snapshots the database with `pg_dump` under an exported transaction snapshot and includes the referenced private signature, PDF, and audit files in a private gzip JSON bundle. It preserves admin access, the audit ledger, and backup files. Limits: 1000 submissions, 64 MB input, 180-second transaction. Larger datasets require the operator procedure.

Backup bundles contain private data and authentication-state snapshots. Download them only to a protected location. Keep the original bundle and verify its hash. For recovery, decompress JSON, decode `database.content` to a pg_dump custom file, restore first into an isolated database with `pg_restore`, and verify record counts and the audit chain. Decode each `files[].content`, verify its SHA-256, and upload it to the recorded key in the matching private bucket. Do not restore the complete database over a live collection or reactivate old sessions. Test the recovery in isolation before any production restoration.

Clearing removes only backed-up test submissions and their original files. If original file deletion fails after the database transaction, the UI reports the number remaining; the backup remains intact. Review the bundle's file list for operator cleanup. No backup purge is provided by this control. Automatic record deletion is disabled pending the campaign-close retention review.
